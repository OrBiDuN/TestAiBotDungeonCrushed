# Управление через Telegram

Запуск: `Start-Telegram.bat`. Также можно открыть обычный Launcher и нажать
«Подключить Telegram / показать привязку». Нужен только один подключённый Launcher.

Токен читается из переменной `DUNGEON_TELEGRAM_TOKEN` или `.env.telegram` рядом
с launcher.py, в формате `DUNGEON_TELEGRAM_TOKEN=...`. Файл исключён из Git.
Не публикуйте его. Чтобы заменить токен, измените значение и перезапустите Launcher.

При первом подключении локально отображается `/pair <код>` (действует 10 минут).
Отправьте эту строку в личный чат @Dungeoncrushed_bot. После привязки появятся
актуальное меню подготовки или управления. Владелец сохраняется в локальном
`.telegram-owner.json`, также исключённом из Git. Для смены владельца закройте
Launcher, удалите этот файл и выполните привязку снова.

После привязки нажмите **«Запустить» → «Бесконечный режим»**.
Тот же сценарий доступен в основном окне программы. Дальше бот сам:

1. Проверяет игру; при отсутствии процесса запускает установленный `dungeoncrusher.exe`.
2. Находит игровое окно, пробуждает его, выбирает всю клиентскую область и включает захват.
3. При распознанном окне другого устройства нажимает «Перезайти» и ждёт загрузки.
4. Определяет текущий экран, открывает осаду и список боссов либо продолжает открытую осаду.
5. Запускает бесконечный режим и сохраняет скриншоты в `screenshots/endless/`.

Каждый этап приходит в Telegram. Во время работы клавиатура содержит только
«Остановить», «Экран» и «Статистика». Каждые 10 минут приходит отдельное сообщение:
время с начала запуска, число завершённых боссов, атак и перезаходов.
Счётчики сохраняются при автоматическом переподключении в рамках текущего запуска.
При закрытии игры бот повторяет запуск и подготовку. Повторное нажатие режима
во время работы не создаёт второй маршрут. СТОП отменяет весь автоматический сценарий.

`/run` открывает выбор режима, `/endless` сразу выбирает бесконечный режим;
`/stop`, `/screen`, `/status` — остановка, экран и статистика.
Технические команды `/find`, `/setup`, `/relogin`, `/desktop` оставлены для диагностики.
Перед их использованием остановите автоматический режим.

Команда `/desktop` или «Восстановить рабочий стол» пытается перенести только
собственный отключённый RDP-сеанс бота на локальную консоль. Сначала отменяются
игровые действия. Бот проверяет подключение в течение 20 секунд и сообщает
результат. После успеха отправьте `/setup`; игровые действия сами не возобновляются.
Рабочий стол может стать видимым на физическом мониторе компьютера.

На этом ПК проверка без повышения прав получила Windows error 5 (доступ запрещён).
Подключившись по RDP, закройте обычный Dungeon Bot, запустите `Start-Admin.bat`
и подтвердите запрос UAC. Затем можно закрыть RDP и отправить `/desktop`.
Сам бот в таком случае работает с правами администратора. Пароль Windows не
сохраняется и не отправляется в Telegram. Повышение прав не гарантирует успех:
бот сообщает фактический результат Windows. Чужой или другой занятый консольный
сеанс не переключается. Win+L и парольный экран входа эта команда не обходит.
СТОП прекращает ожидание и игровые действия, но уже отправленный Windows запрос
переключения отменить нельзя.
При входе с другого устройства в выбранном автоматическом режиме бот сам
выполняет проверенный перезаход и возвращается к осадам. Вне запущенного режима
игровые действия самостоятельно не начинаются. Исчезновение диалога проверяется
на двух новых кадрах, затем ожидается распознанный игровой экран.
Если переход не подтверждён в отведённое время, бот сообщает причину остановки.
Непонятный текст, фото или стикер от владельца возвращают актуальное меню.

СТОП из Telegram отменяет ввод, сохраняя трансляцию; локальный общий СТОП
останавливает также трансляцию. Снимки берутся только из свежего WGC-кадра,
без рабочего стола и без отмены режима. Частота запросов — не чаще раза в 3 секунды.

Временная потеря связи с Telegram не останавливает выбранный автономный режим.
Уведомления имеют ограниченные повторы и срок жизни; после восстановления связи
можно запросить актуальную статистику. Старые команды запуска игнорируются.

Приложение и Windows-сеанс должны оставаться активными. Автоматический запуск
использует путь установленной игры из `targets.py`. Вход в Steam с паролем,
разблокировка Windows и неизвестные игровые диалоги не автоматизированы.
Распознавание маршрутов рассчитано на клиентскую область около 1920×1080.
При неподтверждённом экране бот сообщает причину, вместо клика по случайным координатам.

Реализация использует HTTPS Bot API и long polling без входящего порта:
https://core.telegram.org/bots/api#getupdates

Проверки без игровых кликов:
`.venv\Scripts\python.exe -m unittest test_telegram_control test_stop_regressions -v`
