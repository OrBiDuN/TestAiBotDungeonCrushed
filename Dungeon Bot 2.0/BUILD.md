# EXE и повторная сборка

`Rebuild-Restart.bat` запускает обновление в фоне и сразу возвращает управление.
Он останавливает процессы `DungeonBot*.exe`, вызывает `Build-Exe.bat --no-pause`,
проверяет собранный EXE и запускает `DungeonBot.exe`. При ошибке сборки запуск
отменяется. Журнал — `rebuild-restart.log`, текущий этап —
`rebuild-restart-status.json`. Повторный запуск во время сборки пропускается.
Если старый бот работает от администратора, BAT тоже нужно запускать от администратора.
После доработок использовать этот BAT; завершения фоновой сборки ждать не требуется.

Обновление действий от 16.11.2026: `DungeonBot-human.exe`. Все автоматические
клики (навигация, поиск, атака, выход из боя, окна ОК и перезаход) используют
смещение до ±3 px по X и ±2 px по Y от распознанной точки. Последовательные
действия получают разные смещения. Перед движением — пауза 0,15–0,45 с,
перед кликом — 0,12–0,35 с, примерно в 18% действий дополнительно 0,3–0,8 с.
Движение плавно ускоряется и замедляется; скорость и длительность удержания
кнопки меняются. Интервалы прокрутки — 30–95 мс, иногда 180–320 мс.
Фактические интервалы могут быть больше из-за таймера интерфейса и проверки кадра.
Проверка цели выполняется после паузы, непосредственно перед нажатием;
СТОП/Esc отменяют ожидание. Ручное повторение записанной точки остаётся точным.
Проверка: 110 автоматических тестов, без отправки игровых кликов.

Обновление входа от 06.11.2026: `DungeonBot-login.exe`. В бесконечном режиме
после входа или перезахода бот закрывает окно с золотом кнопкой «ОК», затем
нажимает «Осады» на главном экране и «Осады» в рейтинге. Поиск запускается
после подтверждения списка боссов. Поддерживаемая игровая область — около 1920×1080.

Актуальная версия с автоматическим запуском и скриншотами: `DungeonBot.exe`.
В основном окне и Telegram: «Запустить» → «Бесконечный режим».
Скриншоты сохраняются в `screenshots/endless/<дата-время запуска>/` рядом с EXE.

Запуск готовой программы: `DungeonBot.exe`. Python на компьютере для запуска EXE
не нужен. Telegram подключается автоматически; первая привязка владельца остаётся
такой же, как в [TELEGRAM.md](TELEGRAM.md).

Токен `.env.telegram`, привязка `.telegram-owner.json`, база `data/`, журнал
`siege-actions.jsonl` и папка `screenshots/` находятся рядом с EXE. Они не включены
в исполняемый файл. При переносе программы скопируйте нужные настройки отдельно.
Папка программы должна быть доступна для записи. Игровые шаблоны включены в EXE.

Для пересборки после изменения кода закройте запущенный `DungeonBot.exe` и откройте
`Build-Exe.bat`. Он использует `.venv` или создаёт её через Python Launcher для
Python 3.12, устанавливает зависимости и собирает EXE в эту же папку.
Нужны исходники проекта, Windows x64, Python 3.12 x64 и доступ к PyPI при установке
недостающих зависимостей. Сборщик закреплён в `requirements-build.txt`.
Для автоматического запуска без паузы: `Build-Exe.bat --no-pause`.

Проверка комплектации без подключения Telegram и без игровых действий:
`DungeonBot.exe --build-smoke-test`. Результат — `exe-smoke-result.json`.
Проверяются Qt, загрузка шаблонов, модуль захвата и русский Windows OCR.
Ошибка запуска записывается в `exe-startup-error.log`.

Обновление захвата от 05.11.2026 собрано отдельно в `DungeonBot-updated.exe`,
поскольку основной EXE был запущен. Закройте старый бот и запустите обновлённый
из этой же папки: настройки Telegram и база остаются общими.

Диагностика программы и WGC записывается в `runtime.log` рядом с EXE:
причины разрывов, номера повторов, задержки и восстановление кадров.
Размер ограничен примерно 2 МБ, сохраняются три предыдущих файла.
При временной потере WGC повторные попытки идут с задержками 1, 2, 4, 8,
16, затем 30 секунд; после 10 секунд стабильных кадров задержка сбрасывается.
После разворачивания окна создаётся новый сеанс захвата. Закрытие/замена окна,
изменение калибровки и ручная остановка не запускают бесконечное восстановление.
Действия маршрута ждут свежих кадров, сохраняя отметки уже отправленных команд.

EXE не подписан цифровой подписью. Упаковка не меняет доступность сети Telegram:
при недоступном HTTPS бот не сможет обмениваться сообщениями.

Разделение встроенных ресурсов и файлов рядом с EXE основано на документации:
https://pyinstaller.org/en/stable/runtime-information.html
