# Dungeon Bot 2.0 — Windows Graphics Capture / Steam

Запуск: `Start.bat`. Основная цель — установленный Steam-клиент
`C:\Program Files (x86)\Steam\steamapps\common\Dungeon Crusher Soul Hunters\dungeoncrusher.exe`.

## Подключить Steam

1. Запустите игру самостоятельно.
2. Нажмите «Найти Steam Dungeon Crusher (PID / HWND)».
   Launcher найдёт процесс по имени, выведет PID и HWND, выберет самое большое
   видимое окно процесса и задаст его клиентскую область через существующую калибровку.
3. Нажмите «Начать трансляцию». По умолчанию — 15 FPS. Доступны 5 / 10 / 15 / 30;
   изменение частоты применяется при следующем запуске трансляции.
4. Видеопоток, фактический FPS, размер, счётчик и время последнего кадра отображаются справа.
5. «Остановить трансляцию» освобождает ресурсы WGC без блокировки GUI.
   Повторный запуск работает. Общий СТОП также останавливает ввод мыши.

WGC получает кадры конкретного HWND даже при перекрытии другим окном.
Свёрнутое окно переводит поток в паузу; после разворачивания поток продолжается.
Некоторые полноэкранные игры сами сворачиваются при потере фокуса. Для одновременного
просмотра игры и Launcher используйте оконный режим игры. Launcher не меняет настройки игры.

## Область и координаты

Windows Mouse и `gamearea.py` сохранены. Клики по-прежнему идут через SendInput.
Для Steam начало координат — левый верхний угол клиентской области, без рамки/заголовка.
При переносе окна область и записанная относительная точка перемещаются вместе с ним.
При изменении размера/DPI откалиброванный захват останавливается с конкретной причиной:
нажмите «Использовать всю клиентскую область» либо откалибруйте обрезку заново.
Старую точку после новой калибровки нужно записать заново.

Можно захватывать всё выбранное окно без калибровки. Тогда поток автоматически
принимает новые размеры кадров; это не разрешает некалиброванные игровые клики.
«Калибровать игровую область» оставляет прежний механизм выделения на статичном снимке.
Калибровка и координаты хранятся в памяти текущего сеанса.

Chrome сохранён как дополнительный ручной выбор через «Найти Chrome».
Автоматических проверок URL, CDP, расширений, Native Messaging, DLL injection и
доступа к памяти игры нет. Поиски боссов и атаки не выполняются.

## Технические детали

- `windows-capture==2.0.1`, Windows Graphics Capture, точный `window_hwnd`.
- Native WGC callbacks работают вне GUI; жизненным циклом управляет QThread.
- Ограничение частоты перед копированием кадра совместимо с Windows, где отсутствует
  API MinimumUpdateInterval. На статичном окне WGC может присылать меньше кадров.
- Native BGRA копируется в собственный QImage до возврата callback. GPU-буфер не удерживается.
- Хранится только последний кадр, а не очередь. GUI забирает свежий кадр по таймеру.
- `Launcher.latest_video_frame()` — доступ к актуальному кадру для будущего CV по запросу.
  Возвращаемый QImage нельзя менять. При остановке/паузе актуального кадра нет.
- Кадры потока не пишутся на диск. OCR/OpenCV-распознавание отсутствует.
  OpenCV устанавливается как зависимость windows-capture, но распознавание не запускается.
- FPS рассчитан по последним 60 временам получения кадров. Во время остановки/застоя — 0.
- «Копирование» — время обработки callback. «Возраст кадра WGC» доступен только когда
  источник даёт сопоставимую временную метку; это не полный замер задержки до монитора.
- Ошибки устройства, размера, DPI, недоступного окна выводятся явно. Автоперехода
  к другому механизму или управлению браузером нет.

## Проверка без игры

Кнопка «Тестовое окно с анимацией», затем «Начать трансляцию».
Она открывает собственное окно с движущимся прямоугольником и счётчиком.

```powershell
.\.venv\Scripts\python.exe launcher.py --live-demo
.\.venv\Scripts\python.exe launcher.py --live-benchmark
```

Бенчмарк длится около 45 секунд и проверяет пиксельные изменения, FPS, потребление памяти,
отзывчивость GUI, остановку/перезапуск, обрезку, перенос, изменение размера и сворачивание.
Он не отправляет клики и работает только со своим тестовым окном.
Отчёт — `live-benchmark.json`. `--steam-check` измеряет доступный игровой поток 20 секунд
без ввода и сохраняет `steam-capture-result.json`; после проверки поток остаётся включённым.
`--steam-live` выбирает найденный Steam HWND и запускает поток без измерительного теста.

Для установки зависимостей: `.venv\Scripts\python.exe -m pip install -r requirements.txt`.
Ручная запись физического клика и реальные переключения DPI между мониторами остаются
отдельными пользовательскими проверками предыдущих этапов.

## Автоматическое пробуждение окна

Перед маршрутом и действием мыши Launcher восстанавливает выбранное свёрнутое окно,
запрашивает передний план и проверяет, что HWND действительно получил фокус.
Маршрут после этого ждёт новый кадр WGC; координаты пересчитываются после восстановления.
При потере фокуса между шагами пробуждение повторяется. Изменение калибровки не требуется.
Если Windows не разрешила активацию за 4 секунды, действие завершается с причиной без клика.
СТОП/Esc отменяют ожидание. Запускайте маршрут кнопкой в Launcher.

Проверка `wake_selfcheck.py` использует два собственных окна и кликает только по своей
кнопке запуска: проверяет восстановление свёрнутого окна, активацию открытого неактивного
окна и отмену ожидающего пробуждения. Результат находится в `wake-selfcheck.json`.

## Подсветка и поиск боссов

На трансляции автоматически определяется главный экран, рейтинг осады, список осад
или меню босса. Зелёная рамка показывает распознанную кнопку «Выследить босса».
Распознавание выполняется отдельным потоком с одним актуальным кадром и результатом;
при устаревании кадра подпись сообщает об отсутствии свежего изображения.
Поддерживается текущая раскладка около 1920×1080 и вся клиентская область.

Откройте в игре «Осады» и нажмите «Найти боссов: нажимать “Выследить” до исчезновения».
Окно восстанавливается и активируется. Мышь перемещается к найденной кнопке и нажимает её.
После каждого нажатия координаты определяются заново по свежему кадру.
Поиск останавливается при исчезновении кнопки на нескольких свежих кадрах,
неподтверждённом перемещении после клика, ошибке, СТОП/Esc или после 4 поисков.
Этот режим не атакует и не ищет кланового босса. Параметры ручного клика не изменены;
для нового режима используется короткое движение и пауза с проверкой кнопки перед нажатием.

Проверки: `python -m unittest test_boss_search test_route_start -v`.
Они проверяют распознавание предоставленных изображений и логику повторного поиска
без отправки игровых кликов. Это не доказательство успешного прохождения в игре.

### Карточки и лимит осад

Голубые рамки отмечают видимые карточки, включая распознанный верх четвёртой карточки.
Счётчик «Видно боссов: N/4» относится к текущему изображению, а не к сумме карточек
на разных позициях прокрутки. Лимит поиска — четыре одновременно; уже видимые боссы
учитываются до первого нажатия. Отправленный поиск резервирует одно место до конца запуска.

Если при запущенном поиске кнопка скрыта и видны ровно три карточки, бот перемещает
мышь внутрь списка и прокручивает вниз на два деления колеса. Затем ждёт свежий кадр.
За запуск разрешено не более двух таких прокруток. При обнаружении четвёртой карточки
поиск прекращается. Пассивное распознавание не прокручивает и не нажимает кнопки.

Проверено на двух предоставленных скриншотах (3 карточки / 3 и частичная четвёртая),
в том числе размещённых в полном кадре 1920×1080, и тестом переходов прокрутки/лимита
без реального игрового ввода: `python -m unittest test_cardvision test_boss_search test_route_start -v`.

### Живой журнал карточек и открытие босса

Windows OCR с установленным русским языком читает полные видимые карточки сверху вниз:
имя, очки, текущее / максимальное HP. Чтение выполняется в фоновом потоке не чаще раза
в секунду. Журнал получает новый блок при изменении данных, без одинаковых записей
на каждом кадре; хранится максимум 1000 строк интерфейса. Неразобранное поле отмечается
знаком «?», частичная карточка не получает выдуманных данных.

Кнопка «Найти боссов → прочитать → Атаковать первую карточку» после поиска/достижения
лимита ждёт свежего OCR и открывает первую полностью видимую прочитанную карточку
с ненулевым HP. Перед нажатием снова проверяются положение кнопки и изображение имени.
После единственного нажатия проверяется появление меню босса; автоматического нажатия
«Атака» внутри меню в этом режиме нет. СТОП/Esc отменяют весь процесс.

После прокрутки сбрасывается прежнее положение кнопки поиска и выдерживается 0,7 с
для обновления списка. Сила прокрутки по запросу пользователя — 100 делений.

Проверки: `python -m unittest test_boss_ocr test_cardvision test_boss_search test_route_start -v`.
Проверены данные двух пользовательских скриншотов, фоновое чтение, порядок карточек,
переход к одному нажатию и подтверждение меню на моделируемых кадрах. Эти проверки
не означают фактическое выполнение игрового клика.

### Текущий алгоритм: без HP, прокрутка вниз и возврат вверх

HP больше не читается, не выводится в лог и не используется для разрешения нажатия.
Читаются только имя и очки. Перед нажатием нужны два одинаковых результата OCR
на разных свежих кадрах и полностью видимая первая карточка у начала списка.

Прокрутка изменена: вместо одного события с delta=12000 отправляется 100 отдельных
событий колеса по 120, с интервалом таймера 10 мс и проверкой окна/курсора на каждом
шаге. СТОП/Esc прерывают серию. Вниз прокручивается поиск скрытой кнопки; после окончания
поиска выполняется 100 делений вверх, ожидание свежих кадров и нажатие «Атаковать»
в первой карточке. Нажатие обычной «Атака» внутри меню этим режимом не выполняется.

Семь тестов проходят, включая 100 событий вниз, 100 вверх, прекращение ввода после
СТОП и выбор карточки после двух чтений. Реальная реакция игры на серию требует проверки.

### Ночной режим одной обычной атаки

Отдельная кнопка «Поиск → первый босс → 1 обычная атака» продолжает открытие первой
карточки одним нажатием обычной «Атака». Прежний режим открытия карточки сохранён.
Кнопка проверяется на свежем кадре непосредственно перед вводом; повтор после
неподтверждённого перехода не выполняется. Смена экрана не считается доказательством победы.
Исправлен таймаут нестабильного OCR; прокрутка прекращается при устаревшем кадре WGC.
Тесты: test_night_regressions вместе с test_boss_ocr, test_cardvision, test_boss_search,
test_route_start — 10 проверок без игровых действий. Живая проверка новой атаки пока не выполнена.

### Проверка очков OCR

Очки читаются с двумя границами области и двумя порогами обработки. При конфликте
цифровых результатов (например, 125 и 1125) поле остаётся неизвестным: бот не восстанавливает
цифру догадкой. Частота чтения остаётся ограниченной фоновым worker; очереди кадров нет.
Проверки согласования: test_score_agreement. Реальный случай потери цифры из игрового
лога пока не подтверждён новым захватом экрана.

### Две отдельные кнопки атаки из открытого меню босса

«Атака — один обычный удар в меню босса» и «На все — атака на все доступные попытки»
работают независимо. Сначала откройте меню босса в игре и включите трансляцию Steam.
Выбранная кнопка Launcher пробуждает окно, распознаёт именно нужную кнопку, наводит
мышь и повторно проверяет её перед одним кликом. При неизвестном исходе повтора нет.
Обе команды взаимно блокируются с другими маршрутами до завершения или СТОП.
В строке текущего экрана показывается обнаружение обеих кнопок.

Проверено: оба шаблона на новом пользовательском скриншоте, разделение двух действий
и запрет повторного нажатия в unit-тестах. Всего 19 тестов проходят. Реальный расход
атак этим изменением автоматически не тестировался.

### Исправление остановки после четырёх боссов (по логу 07:19–07:20)

Выбор первой карточки после возврата вверх больше не зависит от успешного OCR.
На свежих кадрах подтверждаются верхняя полностью видимая карточка, её кнопка
«Атаковать» и неизменность области имени в течение минимум 0,3 с. Перед самим кликом
расположение и изображение снова проверяются. OCR имени/очков используется только
для журнала; неизвестные очки и ошибка OCR не блокируют этот визуальный выбор.
Ложные/неизвестные очки не заменяются догадкой. Ошибка чтения конкретных значений
из пользовательского лога этим изменением не объявляется исправленной.
19 тестов прошли, включая выбор первой карточки при ошибке OCR и сброс устойчивости
при исчезновении карточки. Живая проверка обновлённого перехода ещё требуется.

### Добивание босса и возврат

«Поиск → первый босс → добить → Назад» продолжает поиск циклом обычных атак.
«Добить босса в открытой карточке → Назад» запускает тот же цикл из меню босса.
Каждая атака требует свежего распознавания; следующий шаг — крестик справа сверху
при подтверждённом экране боя (крестик плюс надпись «Ход»), затем ожидание карточки.
Новая атака разрешена только после возврата. По надписи «Осада данного босса завершена»
нажимается «Назад» и проверяется список осад. Исчезновение кнопки без этой надписи
само по себе не считается завершением. При нехватке доступных атак или неизвестном
экране цикл останавливается по таймауту; покупки/восполнение попыток не выполняются.
Предел одного запуска: 50 обычных атак или 10 минут. СТОП/Esc отменяют работу.
Проверено распознавание новых вложений и тесты переходов без игровых кликов;
фактическое добивание в игре пока не проверено.
